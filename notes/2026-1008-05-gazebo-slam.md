# 06. Gazebo와 SLAM으로 지도 만들기

라이다가 달린 TurtleBot3(burger) 로봇을 Gazebo 시뮬레이터에 띄우고, 키보드로 돌아다니게 하면서 **slam_toolbox**로 지도를 만든 뒤 파일로 저장하는 실습입니다.

- 환경: `native` 프로파일 (`ros2-jazzy-native`, M1에서 직접 실행되는 arm64 이미지)
- 검증: 2026-10-08, 실습 환경과 분리된 테스트 환경에서 Gazebo·SLAM·RViz 실행 → 조종 → 지도 저장까지 확인했습니다.
- 참고: [TurtleBot3 e-Manual – SLAM Simulation](https://emanual.robotis.com/docs/en/platform/turtlebot3/slam_simulation/), [slam_toolbox](https://github.com/SteveMacenski/slam_toolbox)

## 전체 구성

```
              /scan(라이다), /odom(바퀴 위치), /tf
Gazebo ─────────────────────────────────────────────▶ slam_toolbox ──/map──▶ RViz (지도 보기)
(TurtleBot3 + 월드)                                         │
     ▲                                                     └──/map──▶ map_saver_cli (파일 저장)
     └──────────── /cmd_vel ──── teleop_keyboard (키보드 조종)
```

| 이름 | 하는 일 |
|---|---|
| **Gazebo** | 로봇과 주변 환경(벽, 기둥)을 물리적으로 시뮬레이션합니다. 라이다 측정값도 만들어 냅니다 |
| **SLAM** (slam_toolbox) | 라이다와 로봇의 이동 정보를 합쳐 **지도를 만들면서 동시에 지도 위의 내 위치를 추정**합니다 (Simultaneous Localization And Mapping) |
| **RViz** | 만들어지는 지도, 라이다 점, 로봇 위치를 화면에 보여 줍니다 |
| **map_saver_cli** | 완성한 지도를 이미지(`.pgm`)와 설정(`.yaml`) 파일로 저장합니다 |

## 명령을 붙여 넣는 곳

- **Mac 터미널 (레포 루트):** 이 레포를 클론한 폴더(`compose.yaml`이 있는 곳)로 이동한 뒤 실행하세요.
- **컨테이너 안 (native):** `docker compose exec native bash`로 들어간 셸입니다. 이번 실습은 `desktop-full`이 아니라 **`native` 컨테이너**를 씁니다.

## 0. 준비: native 환경 띄우기

**왜 native인가:** `osrf/ros` 이미지(`desktop-full`)는 Intel용이라 M1에서 Rosetta로 번역해 실행되는데, 이때 Gazebo 창이 시작 단계에서 멈춥니다(README의 "M1 호환성" 참고). `native` 이미지는 M1에서 직접 실행되므로 Gazebo 창이 정상으로 뜹니다.

**이미지에 들어 있는 것:** `docker/native/Dockerfile`에 이 실습에 필요한 패키지를 넣어 두었습니다.

| 패키지 | 용도 |
|---|---|
| `turtlebot3_gazebo`, `turtlebot3_teleop` | TurtleBot3 시뮬레이션과 키보드 조종 |
| `slam_toolbox` | SLAM |
| `nav2_map_server` | 지도 저장 (`map_saver_cli`) |
| `nav2_bringup` | 지도·라이다·로봇을 보여 주는 RViz 설정 파일 |

TurtleBot3 명령이 요구하는 로봇 모델 값(`TURTLEBOT3_MODEL=burger`)도 이미지에 기본값으로 들어 있어서 따로 `export`하지 않아도 됩니다.

**Mac 터미널 (레포 루트):** native 이미지를 빌드하고 띄웁니다. 처음에는 몇 분 걸립니다. 이전에 native 이미지를 빌드한 적이 있으면 새 패키지만 받으므로 1분 정도면 됩니다.

```bash
docker compose --profile native up -d --build
```

`desktop-full` 컨테이너가 켜져 있다면 CPU를 아끼기 위해 꺼 두는 것을 권합니다. **Mac 터미널 (레포 루트):**

```bash
docker compose stop desktop-full
```

브라우저에서 `http://localhost:8080`을 열거나 새로고침합니다. 이번 실습은 **터미널 4개**가 필요합니다(Gazebo, SLAM, RViz, 조종). Mac 터미널 탭 4개를 열고, 탭마다 레포 루트에서 native 컨테이너에 들어갑니다.

```bash
docker compose exec native bash
```

**컨테이너 안 (native):** 제대로 들어왔는지 확인합니다. `aarch64 burger`가 나오면 정상입니다.

```
echo "$(uname -m) $TURTLEBOT3_MODEL"
```

## 1. Gazebo에 TurtleBot3 띄우기 (터미널 1)

**컨테이너 안 (native):**

```
ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py
```

몇 초 뒤 브라우저에 Gazebo 창이 뜹니다.

- **화면 구성:** 육각형 벽 안에 기둥 9개가 있고, 그 사이에 `burger` 로봇이 놓여 있습니다.
- **실행 속도:** 오른쪽 아래 숫자는 실시간 대비 시뮬레이션 속도로, 테스트에서는 약 89%였습니다.

**컨테이너 안 (native, 터미널 2):** 로봇이 내보내는 토픽을 확인합니다.

```
ros2 topic list
```

`/scan`(라이다), `/odom`(바퀴로 추정한 위치), `/tf`(좌표 관계), `/cmd_vel`(속도 명령), `/clock`(시뮬레이션 시간)이 보이면 정상입니다. 라이다는 초당 약 5번 측정합니다(테스트에서 4.6Hz).

```
ros2 topic hz /scan
```

확인이 끝나면 Ctrl+C로 `hz`를 멈추세요.

## 2. SLAM 실행하기 (터미널 2)

**컨테이너 안 (native):**

```
ros2 launch slam_toolbox online_async_launch.py
```

- `online_async`는 로봇이 움직이는 동안(online) 지도를 계속 갱신하는 모드입니다.
- 시뮬레이션 시간(`use_sim_time`)을 쓰는 설정이 기본값(`true`)이라 따로 지정하지 않아도 됩니다.
- `maximum laser range setting (20.0 m) exceeds the capabilities of the used Lidar (3.5 m)` 경고는 설정값보다 라이다 성능이 낮다는 안내라 무시해도 됩니다.

## 3. RViz로 지도 보기 (터미널 3)

**컨테이너 안 (native):** Nav2에 들어 있는 RViz 설정 파일로 띄웁니다. `use_sim_time:=true`는 RViz도 Gazebo의 시뮬레이션 시간에 맞추라는 뜻입니다.

```
rviz2 -d /opt/ros/jazzy/share/nav2_bringup/rviz/nav2_default_view.rviz --ros-args -p use_sim_time:=true
```

| 색 | 뜻 |
|---|---|
| 흰색 | 비어 있는 공간 (지나갈 수 있음) |
| 검은색 | 벽·기둥 같은 장애물 |
| 회색 | 아직 탐색하지 않은 곳 |
| 빨간 점 | 지금 라이다가 측정한 점 |

오른쪽의 Docking, Selector 패널은 다음 단계(Nav2 자율주행)용입니다. 지금은 쓰지 않으니 패널의 X를 눌러 닫아도 됩니다.

## 4. 로봇을 조종해서 지도 그리기 (터미널 4)

**컨테이너 안 (native):**

```
ros2 run turtlebot3_teleop teleop_keyboard
```

| 키 | 동작 |
|---|---|
| `w` / `x` | 전진 속도 올리기 / 내리기 (한 번에 0.01m/s, burger 최대 0.22m/s) |
| `a` / `d` | 회전 속도 올리기 / 내리기. 양수면 왼쪽, 음수면 오른쪽으로 돕니다 (burger 최대 2.84rad/s) |
| 스페이스, `s` | 정지 |
| Ctrl+C | 조종 끝내기 |

지도 그리기 요령입니다.

- **키 입력:** 키는 **터미널 4 창**을 클릭해 둔 상태에서 누르세요.
- **속도:** `w`를 5~10번 눌러 0.05~0.1m/s 정도로 천천히 움직이세요. 빠르게 움직이거나 급하게 회전하면 지도가 틀어질 수 있습니다.
- **목표:** RViz에서 **회색 영역이 없어지도록** 벽을 따라 한 바퀴 돌고, 기둥 사이도 지나가세요.
- **충돌 주의:** 벽에 부딪히기 전에 스페이스로 멈추세요.

⚠️ Jazzy의 TurtleBot3는 `/cmd_vel` 메시지 타입이 `geometry_msgs/msg/TwistStamped`입니다. turtlesim처럼 `geometry_msgs/msg/Twist`로 `ros2 topic pub`을 보내면 로봇이 움직이지 않습니다. 타입은 아래 명령으로 확인할 수 있습니다.

```
ros2 topic info /cmd_vel
```

## 5. 지도를 파일로 저장하기

지도가 다 그려지면 터미널 4에서 Ctrl+C로 조종을 끝내고, 같은 터미널에서 저장합니다. 저장은 SLAM이 내보내는 `/map`을 받아서 하므로 **SLAM(터미널 2)은 켜 둔 채로** 저장하세요.

**컨테이너 안 (native):**

```
mkdir -p ~/data/maps && ros2 run nav2_map_server map_saver_cli -f ~/data/maps/turtlebot3_world
```

`Map saved successfully`가 나오면 레포의 `data/maps/`에 두 파일이 생깁니다.

| 파일 | 내용 |
|---|---|
| `data/maps/turtlebot3_world.pgm` | 지도 이미지. 흰색 = 빈 공간, 검은색 = 장애물, 회색 = 미탐색 |
| `data/maps/turtlebot3_world.yaml` | 지도 설정. 이미지 파일 이름, 해상도, 원점 위치 등 |

`turtlebot3_world.yaml`의 주요 항목입니다.

```yaml
image: turtlebot3_world.pgm     # 지도 이미지 파일
resolution: 0.050               # 한 픽셀 = 0.05m (5cm)
origin: [-0.937, -2.080, 0]     # 이미지 왼쪽 아래 모서리의 실제 위치 (x, y, 회전). 값은 실행마다 다름
occupied_thresh: 0.65           # 이 값보다 어두우면 장애물로 판단
```

**Mac 터미널 (레포 루트):** `.pgm` 파일을 PNG로 바꿔서 Mac에서 열어 볼 수 있습니다.

```bash
sips -s format png data/maps/turtlebot3_world.pgm --out data/maps/turtlebot3_world.png
```

지도 파일은 10KB 정도로 작고(테스트에서 `.pgm` 11KB) `.gitignore`에 걸리지 않으므로 커밋해 두면 다음 실습(Nav2 자율주행)에서 쓸 수 있습니다.

## 6. 종료하기

각 터미널에서 Ctrl+C를 누르세요. 조종 → RViz → SLAM → Gazebo 순서로 끄면 됩니다.

- **RViz 종료 메시지:** RViz를 끌 때 비정상 종료 메시지(종료 코드 `-6`)가 나올 수 있습니다. 종료 과정에서 생기는 메시지라 무시해도 됩니다.
- **남은 Gazebo 확인:** 끈 뒤 Gazebo 서버가 남아 있지 않은지 확인합니다. **컨테이너 안 (native):** 아무것도 출력되지 않으면 정상입니다.

```
pgrep -fa "gz sim"
```

남아 있다면 아래 명령으로 끄세요. 남은 서버가 있는 채로 다시 실행하면 Gazebo가 두 개 떠서 충돌합니다.

```
pkill -f "gz sim"
```

## 7. 응용: launch 파일 하나로 실행하기

1~3장은 터미널 3개(Gazebo, SLAM, RViz)가 필요합니다. [05. launch](2026-1008-04-launch.md)에서 만든 `turtle_robot` 패키지에 launch 파일을 추가하면 한 번에 실행할 수 있습니다. 조종용 터미널까지 합쳐 **터미널 2개**면 됩니다.

준비 조건은 [04. 패키지](2026-1008-03-ros2-package.md)와 [05. launch](2026-1008-04-launch.md)를 마친 상태입니다. `ws/src/turtle_robot`이 있고, `setup.py`에 `launch/*.launch.py` 설치 설정이 들어 있어야 합니다.

**컨테이너 안 (native):** launch 파일을 만듭니다. 블록 전체를 붙여 넣으세요.

```
cat > ~/ros2_ws/src/turtle_robot/launch/slam.launch.py <<'EOF'
"""Gazebo(TurtleBot3 월드) + SLAM + RViz를 한 번에 실행합니다."""

from launch import LaunchDescription
from launch.actions import IncludeLaunchDescription, SetLaunchConfiguration
from launch.launch_description_sources import PythonLaunchDescriptionSource
from launch.substitutions import PathJoinSubstitution
from launch_ros.actions import Node
from launch_ros.substitutions import FindPackageShare


def generate_launch_description():
    # 터미널 1에서 하던 일: ros2 launch turtlebot3_gazebo turtlebot3_world.launch.py
    world = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(PathJoinSubstitution(
            [FindPackageShare('turtlebot3_gazebo'), 'launch', 'turtlebot3_world.launch.py'])),
    )

    # 터미널 2에서 하던 일: ros2 launch slam_toolbox online_async_launch.py
    slam = IncludeLaunchDescription(
        PythonLaunchDescriptionSource(PathJoinSubstitution(
            [FindPackageShare('slam_toolbox'), 'launch', 'online_async_launch.py'])),
        launch_arguments={'use_sim_time': 'true'}.items(),
    )

    # 터미널 3에서 하던 일: rviz2 -d .../nav2_default_view.rviz --ros-args -p use_sim_time:=true
    rviz = Node(
        package='rviz2',
        executable='rviz2',
        output='screen',
        arguments=['-d', PathJoinSubstitution(
            [FindPackageShare('nav2_bringup'), 'rviz', 'nav2_default_view.rviz'])],
        parameters=[{'use_sim_time': True}],
    )

    return LaunchDescription([
        # Ctrl+C 후 각 프로세스가 스스로 끝나기를 기다리는 시간 (기본 5초).
        # 노드가 많아 부하가 크면 Gazebo 서버가 5초 안에 못 끝나서 강제 종료되고,
        # 이때 실제 서버 프로세스(gz sim -s)가 남는 문제가 있어 15초로 늘린다.
        SetLaunchConfiguration('sigterm_timeout', '15'),
        world,
        slam,
        rviz,
    ])
EOF
```

| 코드 | 뜻 |
|---|---|
| `IncludeLaunchDescription(...)` | 다른 패키지의 launch 파일을 그대로 불러와 실행합니다 (`ros2 launch 패키지 파일`과 같음) |
| `launch_arguments={...}` | 불러온 launch 파일에 인자를 넘깁니다 (`이름:=값`과 같음) |
| `SetLaunchConfiguration('sigterm_timeout', '15')` | Ctrl+C 후 종료를 기다리는 시간을 15초로 늘립니다 |

`SetLaunchConfiguration` 줄을 넣은 이유가 있습니다. 이 줄 없이 테스트했더니 Ctrl+C 후 Gazebo 서버가 5초 안에 끝나지 못해 강제 종료됐고, 실제 서버 프로세스(`gz sim -s`)가 남았습니다. 15초로 늘린 뒤에는 2번 모두 정상 종료됐습니다.

**컨테이너 안 (native):** `package.xml`에 실행할 때 필요한 패키지를 추가합니다. 05장에서 넣은 `turtlesim` 줄 아래에 4줄이 들어갑니다.

```
sed -i 's#  <exec_depend>turtlesim</exec_depend>#  <exec_depend>turtlesim</exec_depend>\n  <exec_depend>turtlebot3_gazebo</exec_depend>\n  <exec_depend>slam_toolbox</exec_depend>\n  <exec_depend>nav2_bringup</exec_depend>\n  <exec_depend>rviz2</exec_depend>#' ~/ros2_ws/src/turtle_robot/package.xml && grep exec_depend ~/ros2_ws/src/turtle_robot/package.xml
```

**컨테이너 안 (native):** 새 launch 파일을 추가했으므로 다시 빌드하고 실행합니다.

```
cd ~/ros2_ws && colcon build --symlink-install --packages-select turtle_robot && source install/setup.bash
```

```
ros2 launch turtle_robot slam.launch.py
```

다른 터미널에서 4장의 `teleop_keyboard`로 조종하고, 5장 명령으로 저장하면 됩니다.

- **종료:** launch 터미널에서 Ctrl+C 한 번이면 모두 종료됩니다. Gazebo 창을 닫아도 전체가 종료됩니다(TurtleBot3 launch의 설정).
- **`ws/` 빌드 결과:** `turtle_robot`은 Python 패키지라 `desktop-full`에서 빌드한 결과도 대개 그대로 쓸 수 있습니다. 빌드나 실행에 문제가 생기면 Mac 터미널(레포 루트)에서 `rm -rf ws/build ws/install ws/log`로 지우고 native 컨테이너에서 다시 빌드하세요.

## 문제 해결

| 증상 | 원인 | 해결 |
|---|---|---|
| Gazebo 창이 뜨지 않고 멈춤 | `desktop-full`(Intel) 컨테이너에서 실행함 | `docker compose exec native bash`로 들어간 native 컨테이너에서 실행 |
| `Package 'turtlebot3_gazebo' not found` | 패키지가 없는 이미지(`desktop-full` 또는 패키지 추가 전의 native) | Mac 터미널(레포 루트)에서 `docker compose --profile native up -d --build` |
| 로봇이 움직이지 않음 | `/cmd_vel`에 `Twist` 타입으로 보냄 | `teleop_keyboard` 사용 (타입은 `TwistStamped`) |
| 다시 실행했더니 로봇이 두 대이거나 이상하게 동작 | 이전 Gazebo 서버가 남아 있음 | `pgrep -fa "gz sim"`으로 확인 후 `pkill -f "gz sim"` |
| `could not connect to display novnc:0` | GUI 서버(noVNC)가 시작하지 못함 | [02. Python 노드 실행](2026-1008-01-run-python-script.md)의 문제 해결 참고 |
